一句话讲清

DHT11 是单总线数字传感器：一根 DATA 线上按"谁拉低、拉多久"传数据，40bit = 湿度16 + 温度16 + 校验8。驱动的本质就是掐着微秒级时序读电平。

接线（3 根）

DHT11核心板
VCC3.3V
DATAPB12（与官方例程 [29] 一致）
GNDGND
裸件（无模块板）需 DATA 上拉 4.7K~10K 到 3.3V；模块自带，不用加。

时序（考试和排障都考这个）

主机起始: ──拉低≥18ms──┬─拉高20~40us─┬────────────── ↓ 释放总线 DHT应答: ┌─低 80us─┐┌─高 80us─┐ 数据40bit: 每 bit = 低50us 起始 + 高电平判 0/1 高 26~28us = "0" 高 ~70us = "1" 字节: 湿度整数.湿度小数 | 温度整数.温度小数 | 校验和 校验: 前4字节相加的低8位 == 第5字节，否则本次作废

驱动骨架（GPIO 输出↔输入切换 + us 延时）

/* 1. CubeMX: PB12 配 GPIO_Output（名字 DHT11_DATA），另启用一个 TIM 做 us 级延时
   2. 读一帧的核心流程 */
DHT11_MODE_OUTPUT();
HAL_GPIO_WritePin(DHT11_PORT, DHT11_PIN, 0);   /* 起始：拉低 ≥18ms */
HAL_Delay(20);
HAL_GPIO_WritePin(DHT11_PORT, DHT11_PIN, 1);
delay_us(30);
DHT11_MODE_INPUT();                            /* 释放，等应答 */

wait(低, 100us); wait(高, 100us); wait(低, 100us);   /* 应答 80-80-80 */
for (i = 0; i < 40; i++) {
    wait(高, 100us);            /* 度过 50us 低电平 */
    计时高电平时长 t;
    bit = (t > 40us) ? 1 : 0;   /* 26~28us=0，70us=1 */
}
/* 3. 校验和通过才采用本帧 */
官方例程 [29] 用 DWT 计数器做 us 延时——直接借用它的 bsp_dwt.c，比自写定时器延时更省事。

当堂任务（约 80 min）

  1. 每 2s 读一次并 printf：T:25C H:41%（用上次课的串口）
  2. 手心捂住传感器 30s，数据记录表记 10 组（时间/温度/湿度），画出温度上升曲线
  3. 故意 500ms 连读两次 → 观察读失败，解释原因（器件 1Hz 上限）
