# 用 STM32CubeMX 导出 Makefile(GCC) 工程 — 学生指南

> 目的：让你的工程能被 `arm-none-eabi-gcc` + `make` 直接命令行编译，便于教师端
> 自动批阅「编译检查」。**默认 CubeMX 生成的是 MDK-ARM(Keil) 工程，里面没有
> Makefile，会被判为「无法编译」。请按本文把工具链改成 Makefile。**

适用：STM32CubeMX 6.x（含 6.17）、Windows、STM32F407ZGTx。

---

## 一、在 CubeMX 里选 Makefile 工具链

1. 用 STM32CubeMX 打开你的 `.ioc` 工程（`.ioc` 是工程唯一事实来源；`.uvprojx` 只是生成产物，丢了也能重生成）。
2. 顶部切到 **Project Manager** 标签页。
3. 左侧选 **Project**。
4. 在 **Project Settings** 区，把 **Toolchain / IDE** 下拉框选成 **`Makefile`**（单词、首字母大写，与 `MDK-ARM` / `STM32CubeIDE` / `EWARM` 并列）。
   - 6.17（RN0094）起新增了原生 **`CMake`** 选项，本课程**统一用 `Makefile`**，不要选 CMake。
5. 填好 Project Name / Project Location；**Firmware package version** 保持默认即可。
6. 左侧切到 **Code Generator**，确认：
   - 勾选 `Copy only the necessary library files`（减小体积）；
   - 勾选 `Generate peripheral initialization as a pair of ".c/.h" files per peripheral`（字段名以你界面实际为准）。
7. 点右上角 **GENERATE CODE**。完成后弹窗点 **Open Folder**。

生成后，工程根目录会出现：

```
你的工程/
├── Makefile                    ← 关键：编译脚本（无扩展名）
├── STM32F407ZGTx_FLASH.ld      ← 链接脚本
├── startup_stm32f407xx.s       ← 启动文件
├── Core/                       ← 你的 main.c 等
├── Drivers/                    ← HAL/CMSIS 库
└── 你的工程.ioc
```

> 改 Toolchain **不会丢失你写的代码**：用户代码都在 `/* USER CODE BEGIN ... */` 与
> `/* USER CODE END ... */` 之间，CubeMX 重新生成时会保留。

## 二、安装编译工具链（Windows，只需一次）

### 2.1 arm-none-eabi-gcc（编译器）

任选一种来源：

- **Arm 官方安装包（推荐）**：<https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads>
  下载 Windows 版 `.exe`，安装时勾选 **「Add path to environment variable」**，把 bin 目录加入 PATH。
- 或命令行：`winget install Arm.GnuArmEmbeddedToolchain`（装完手动把 bin 加入 PATH）。
- 或直接复用 **STM32CubeIDE 自带**的 GCC（装 CubeIDE 后，在其 `plugins/com.st.stm32cube.ide.mcu.externaltools.gnu-tools.../bin` 下）。

**验证**：新开一个终端，执行

```bash
arm-none-eabi-gcc --version
```

能打印版本号即装好。STM32F4（Cortex-M4F）用 12.x / 13.x LTS 均可。
> 注意：要用 **Arm 官方/xPack 的完整包**（带 newlib-nano），不要用极简裸 GCC，否则链接时报 `lc_nano` 找不到。

### 2.2 make

任选一种：

- **MSYS2（推荐）**：<https://www.msys2.org/> 装好后，在 MSYS2 终端执行 `pacman -S make`，再把 `C:\msys64\usr\bin` 加入系统 PATH，即可在普通 cmd/PowerShell 里直接 `make`。
- 或用 **STM32CubeIDE 自带的 `mingw32-make`**（命令名是 `mingw32-make`，可 `doskey make=mingw32-make $*` 起别名）。

## 三、编译

在**工程根目录**（`Makefile` 所在目录）打开终端：

```bash
make            # 编译，产物在 build/ 下（.elf / .hex / .bin）
make clean      # 清理
make -j4        # 并行编译（首次建议先单线程 make 确认无误）
```

如果 `arm-none-eabi-gcc` 没加入 PATH，也可以临时指定：

```bash
make GCC_PATH=C:/Program Files (x86)/Arm GNU Toolchain arm-none-eabi/13.3/bin
```

> 变量名是 **`GCC_PATH`**（不是 BINPATH——那是旧版/第三方叫法，6.x Makefile 里没有）。

## 四、常见坑（首次编译报错先查这里）

### 坑 1：`No rule to make target 'build/main.o'`（`../../` 前缀）

部分 CubeMX 版本生成的 `Makefile` 里 `C_SOURCES` / `C_INCLUDES` 带 `../../` 前缀。
两种解法二选一：

- **A**：从工程根的**父目录**跑 `make`（`../../` 正好指回工程根）；
- **B**：把 `Makefile` 里所有 `../../` 前缀去掉，再在工程根跑 `make`，并把修正版 Makefile **纳入 git**（避免下次重新生成又被覆盖；注意重新生成时是「追加重复路径」而非简单还原，去前缀后请检查无重复条目）。

### 坑 2：`arm-none-eabi-gcc: No such file or directory`

工具链没加入 PATH。回到 2.1 把 bin 目录加进系统 PATH，重开终端再试。

### 坑 3：链接报 `lc_nano` 找不到

装的是极简裸 GCC，换成 Arm 官方/xPack 的**完整包**。

## 五、已经交了 MDK-ARM（只有 .uvprojx）怎么办

最低成本路径：用 CubeMX 打开原 **`.ioc`** → Toolchain/IDE 改成 **Makefile** → 重新 GENERATE CODE。用户代码不丢（见上文 USER CODE 块说明）。

只有 `.uvprojx`、连 `.ioc` 都没有时，才用第三方工具兜底：

- [CubeMX2Makefile](https://github.com/baoshi/CubeMX2Makefile)：从 MDK-ARM/SW4STM32 工程生成 Makefile（成本较高，仅兜底）。

> 不建议「CubeMX 生成 MDK-ARM → 用 STM32CubeIDE 转」：CubeIDE 内部 Makefile 是 IDE 托管的、不打算导出复用，不构成可移植的命令行 make 工程。

---

## 六、提交规范（重要）

为了让教师端 `make` 一键验证编译，提交时请：

1. **只交 CubeMX 原生 Makefile 工程**（含 `Makefile`、`Core/`、`Drivers/`、`.ld`、`startup_*.s`、`.ioc`），**不要只交 `.uvprojx`**；
2. 在 README 里写明工具链版本：`arm-none-eabi-gcc --version` 的输出；
3. 工程根目录要能直接 `make` 通过（自行先编译一次再提交）；
4. 打包时把整个工程文件夹压成 **`.zip`**（教师端也能解 `.7z`，但 `.zip` 兼容性最好）。

这样批阅端的「编译检查」就能真实编译你的工程、给出通过/失败，而不是因缺 Makefile 被判「无法评估」。
